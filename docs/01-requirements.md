# CodeYF 编程智能体需求规格说明书

文档版本：1.0  
状态：实现基线  
目标读者：产品设计者、开发者、测试者、课程/项目评审者

## 1. 项目目标

CodeYF 是一个运行在用户本机的编程智能体。用户用自然语言描述编程任务后，系统通过大语言模型生成决策，按需读取和修改工作区文件、检索代码、执行命令并观察结果，循环推进任务，最后给出可验证的完成报告。

本项目的核心目标不是包装现成 Agent，而是自行实现智能体的关键运行机制：

- 对话历史和上下文预算管理；
- 模型请求、响应解析和 tool calling 协议适配；
- 本地工具定义、参数校验和执行；
- 任务循环、停止条件、失败恢复和重试；
- 文件系统边界、命令风险控制和人工审批；
- 可观测日志、会话持久化和结果汇报。

## 2. 范围

### 2.1 首个版本包含

- 交互式和单次运行两种 CLI 使用方式；
- OpenAI 兼容模型服务接入；
- 系统提示词、用户消息、助手消息、工具调用与工具结果的历史维护；
- 文件读取、文件写入/补丁、文件检索、文本检索、命令执行工具；
- 基于模型 tool calling 的多轮执行循环；
- 最大轮次、超时、取消、显式完成和无工具响应等终止条件；
- 工作区沙箱、危险命令拦截和按策略审批；
- API/工具错误标准化、有限重试和可读错误提示；
- 结构化事件日志与会话保存；
- 最终修改摘要、验证结果和未解决问题说明。

### 2.2 首个版本不包含

- 基于浏览器的 IDE 或图形界面；
- 多智能体协作与任务调度；
- 云端托管的代码执行环境或文件存储；
- 语义索引、向量数据库和仓库级 RAG；
- GitHub/GitLab 自动提交、推送或创建合并请求；
- 自动安装系统级依赖；
- 对容器提供强安全隔离的承诺。

以上能力可作为后续版本扩展，但不得改变“核心循环与本地工具由本项目实现”的约束。

## 3. 用户与典型场景

### 3.1 目标用户

- 希望让模型在本地仓库中完成明确编程任务的开发者；
- 学习或研究 Coding Agent 工作原理的学生与工程师；
- 需要可审计、可替换模型后端的个人用户。

### 3.2 典型任务

1. “为这个 Python 项目增加一个 `/health` 接口并补测试。”
2. “定位测试失败的原因，只做诊断，不修改文件。”
3. “重构重复的校验逻辑，运行现有测试确认没有回归。”
4. “阅读项目并解释认证流程。”
5. “根据错误日志修复构建问题，不能新增依赖。”

## 4. 运行假设与约束

- 用户必须显式指定或确认一个工作区目录。
- 模型服务可通过 HTTP(S) 访问，且由用户提供凭据。
- 本地进程拥有工作区内必要的文件权限。
- 系统不信任模型产生的路径、命令和工具参数；所有参数必须在执行前校验。
- 不使用 LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen、CrewAI 等 Agent 框架或 SDK。
- 可使用模型厂商 API 客户端库、通用 HTTP 客户端、数据校验库和终端 UI 库。
- 不使用 API 服务端托管的代码解释器、文件搜索或 Files API；所有项目文件操作和命令执行均在本地实现。

## 5. 功能需求

### 5.1 启动与任务输入

**FR-001 工作区初始化（MUST）**  
系统必须接受工作区路径，解析为规范绝对路径，确认目录存在，并记录为本次会话的唯一文件操作根目录。
Web 模式必须允许用户在创建新任务前选择工作区；每个任务必须固化自己的工作区，切换其他任务或更改下一任务的选择不得改变已有任务的文件操作根目录。

**FR-002 单次任务模式（MUST）**  
系统必须支持从命令参数或标准输入接收一个任务，执行至终止并返回适合脚本判断的退出码。

**FR-003 交互模式（MUST）**  
系统必须支持在同一会话中接收后续用户消息，并保留有效上下文。用户必须可以用命令取消当前轮、清空会话或退出。

**FR-004 启动检查（MUST）**  
系统必须在首次模型请求前检查配置、API 凭据、工作区可访问性和模型名称；错误必须指出缺失项，不得打印密钥。

### 5.2 模型交互

**FR-010 模型适配（MUST）**  
系统必须通过内部统一接口调用 OpenAI 兼容 API，并将模型、基础 URL、超时和采样参数配置化。业务核心不得依赖某个具体厂商的响应类。

**FR-011 工具声明（MUST）**  
每次允许工具调用的模型请求必须附带机器可读的工具名称、说明和 JSON Schema 参数定义。

**FR-012 响应解析（MUST）**  
系统必须正确处理纯文本、单个工具调用、多个工具调用、空响应、截断响应和格式错误。每个工具调用必须保留模型提供的调用标识。

**FR-013 API 错误重试（MUST）**  
对超时、限流和可恢复的 5xx 错误，系统必须执行带抖动的指数退避；默认最多重试 3 次。认证、参数错误等不可恢复错误不得盲目重试。

**FR-014 流式输出（SHOULD）**  
系统应支持流式显示助手文本；工具参数必须聚合完整并通过解析后才可执行。

### 5.3 上下文与历史

**FR-020 历史记录（MUST）**  
系统必须按顺序记录 system、user、assistant 和 tool 消息，并保持工具调用与工具结果一一对应。

**FR-021 上下文预算（MUST）**  
系统必须根据可配置的上下文上限和输出预留量估算输入规模，在请求前阻止明显超限。

**FR-022 工具结果裁剪（MUST）**  
对超长文件内容和命令输出，系统必须限制返回模型的字符数或估算 token 数，保留头尾、标记省略量，并提示模型缩小读取范围。

**FR-023 历史压缩（SHOULD）**  
接近上下文上限时，系统应保留系统提示、最新用户目标、最近交互和关键状态，将较早历史压缩为结构化摘要。摘要必须区分已完成工作、当前状态、约束和待办项。

**FR-024 指令优先级（MUST）**  
系统提示中的安全规则和用户明确约束必须在上下文压缩后继续存在，工具输出中的文本不得被当作更高优先级指令。

### 5.4 本地工具

**FR-030 读取文件（MUST）**  
模型可按相对路径读取 UTF-8 文本文件的指定行区间。工具必须限制单次输出大小，并报告总行数、实际区间和截断状态。

**FR-031 列出/匹配文件（MUST）**  
模型可按 glob 或等价规则检索工作区文件。工具必须跳过默认忽略目录，并限制结果数量。

**FR-032 搜索文本（MUST）**  
模型可在工作区中按文本或正则表达式检索，支持文件过滤、大小写选项和最大匹配数。

**FR-033 修改文件（MUST）**  
系统必须提供一种确定性的局部修改工具（推荐 unified diff/patch）以及创建新文本文件的能力。修改前后必须验证路径边界；补丁上下文不匹配时必须失败，不得猜测写入位置。

**FR-034 执行命令（MUST）**  
模型可在工作区或其子目录中启动本地命令。系统必须捕获标准输出、标准错误、退出码、耗时和超时状态，并限制输出体积。

**FR-035 工具参数校验（MUST）**  
任何工具在产生副作用前必须按其 schema 校验参数。未知字段、缺少必填项、类型错误和非法枚举值必须返回结构化错误。

**FR-036 工具结果回传（MUST）**  
每次工具执行都必须生成包含 `ok`、结果或错误、元数据的标准化结果，并以对应的 tool call ID 加入历史。

**FR-037 并发规则（MUST）**  
首个版本必须顺序执行同一助手消息中的多个工具调用，以保证副作用顺序确定；结果按调用顺序写回历史。

### 5.5 智能体循环

**FR-040 自主循环（MUST）**  
系统必须实现“构建上下文 → 请求模型 → 解析响应 → 执行工具 → 写入结果 → 再次请求模型”的闭环，无需用户逐步驱动。

**FR-041 正常完成（MUST）**  
当模型返回非空最终文本且不含工具调用时，系统应结束当前任务并展示最终文本。系统提示必须要求最终文本包含修改概述和验证情况。

**FR-042 受控终止（MUST）**  
达到最大模型轮次、总时限、连续空响应上限、连续相同失败上限或用户取消时，系统必须停止，不得无限循环。

**FR-043 重复检测（MUST）**  
系统必须检测连续相同工具名与规范化参数的调用；默认连续 3 次相同且无进展时终止或要求模型反思后仅再尝试一次。

**FR-044 任务状态（MUST）**  
运行状态至少包括 `idle`、`running`、`waiting_approval`、`completed`、`failed`、`cancelled`，且状态转换必须写入事件日志。

**FR-045 验证意识（SHOULD）**  
系统提示应要求模型在修改后运行与任务相称的测试、构建或静态检查；无法验证时必须在最终答复中明确说明原因。

### 5.6 安全与审批

**FR-050 路径沙箱（MUST）**  
文件工具必须拒绝工作区外路径，包括绝对路径逃逸、`..`、符号链接/junction 穿越以及大小写或分隔符变体造成的逃逸。

**FR-051 命令工作目录（MUST）**  
命令的工作目录必须解析到工作区内部。不得仅靠字符串前缀判断路径归属。

**FR-052 审批策略（MUST）**  
系统必须至少提供 `strict`、`balanced`、`auto` 三种策略：

- `strict`：所有写文件和命令执行均需确认；
- `balanced`：普通工作区写入自动允许，高风险命令需确认；
- `auto`：工作区内操作自动执行，但命中禁止规则的操作仍拒绝。

默认策略必须为 `balanced`。

**FR-053 高风险操作（MUST）**  
系统必须识别并阻止或请求批准的操作至少包括：工作区外写入、大范围删除、磁盘/分区操作、权限或所有权批量修改、关机/重启、凭据读取、向远程仓库推送、任意网络下载后直接执行。

**FR-054 敏感信息保护（MUST）**  
日志和终端展示必须对配置中的 API key、Authorization 头和已知密钥值脱敏。系统不得主动把环境变量全集发送给模型。

**FR-055 审批可审计（MUST）**  
审批提示必须展示工具、关键参数、原因和影响范围；批准或拒绝必须记录时间与决策，但不得记录敏感值。

### 5.7 会话、日志与结果

**FR-060 事件日志（MUST）**  
系统必须以 JSON Lines 记录会话状态、模型请求摘要、模型响应摘要、工具调用、工具结果、审批和错误事件。模型密钥与完整敏感内容不得落盘。

**FR-061 会话持久化（SHOULD）**  
系统应可保存和恢复消息历史、摘要、工作区标识、模型配置指纹、轮次和终止状态。恢复前必须重新校验工作区。

**FR-062 用户可见进度（MUST）**  
终端必须显示当前阶段、拟执行工具、关键结果与重试信息；不得输出模型隐藏推理。详细原始事件由 `--verbose` 控制。

**FR-063 最终报告（MUST）**  
完成时必须输出：任务结论、修改/发现摘要、执行过的验证、失败或未验证项。机器模式还必须输出稳定的结构化结果。

## 6. 非功能需求

**NFR-001 可移植性**  
核心代码应支持 Windows、macOS 和 Linux。平台相关的 shell 调用与路径处理必须集中封装并有测试。

**NFR-002 性能**  
除模型和用户审批等待外，常规工具调度额外开销的 P95 应小于 100 ms；文本检索应优先调用可用的 `rg`，不可用时使用内置回退实现。

**NFR-003 可靠性**  
单个工具或模型请求失败不得导致进程未捕获异常退出。会产生副作用的工具不得因网络重试而被自动重复执行。

**NFR-004 可测试性**  
模型客户端、工具执行器、审批器、上下文管理器和循环控制器必须可注入替身。核心流程测试不得依赖真实模型或公网。

**NFR-005 可扩展性**  
新增模型适配器或工具时，不应修改循环控制器主体；工具通过注册表和统一协议接入。

**NFR-006 可观测性**  
所有事件必须具有 `session_id`、时间戳、事件类型和单调递增序号；模型调用与工具调用应具有各自关联 ID。

**NFR-007 易用性**  
错误信息必须包含发生了什么、可能原因和可采取的下一步。默认输出面向人类，`--json` 输出面向程序。

**NFR-008 安全性**  
项目提供的是应用层防护，不宣称能抵御恶意本地用户或宿主机提权。README 必须建议在不可信仓库上使用容器或低权限账户运行。

**NFR-009 编码质量**  
公开接口必须有类型标注；核心分支必须有单元测试；格式化、静态检查和测试应由一个项目命令统一执行。

## 7. 业务规则

1. 工具输出是不可信数据，不得覆盖 system/user 指令。
2. 模型说“已完成”不等于任务成功；系统仅保证循环正常结束，最终报告必须披露验证证据。
3. 拒绝审批后，拒绝结果作为工具结果发回模型，由模型选择安全替代方案或结束。
4. 所有写入必须发生在工具层，模型适配器和上下文管理器不得直接修改工作区。
5. 工具调用参数必须先完整解析再执行；流式半成品参数绝不能产生副作用。
6. 命令超时后必须终止该进程，并尽力终止其子进程；结果中必须标记 `timed_out=true`。
7. 默认不跟随指向工作区外部的符号链接或 Windows junction。

## 8. 验收标准

| 编号 | 验收场景 | 预期结果 | 覆盖需求 |
|---|---|---|---|
| AC-001 | 在示例仓库中要求新增纯函数及测试 | 智能体读取相关文件、应用修改、运行测试并给出摘要 | FR-030~045 |
| AC-002 | 模型调用 `read_file` 读取 `../secret.txt` | 工具拒绝，文件内容不进入历史或日志 | FR-050 |
| AC-003 | 模型输出参数缺失的工具调用 | 返回 `INVALID_ARGUMENT`，进程继续并允许模型纠正 | FR-012、035~036 |
| AC-004 | 模型连续返回同一失败命令 3 次 | 循环被重复检测终止或仅允许一次反思重试 | FR-043 |
| AC-005 | 模型服务先返回两次 429 再成功 | 系统退避重试且任务继续，事件日志包含重试次数 | FR-013、060 |
| AC-006 | 命令运行超过配置超时 | 进程及可识别子进程被终止，返回超时错误 | FR-034、042 |
| AC-007 | `balanced` 策略下请求递归删除 | 执行前展示审批；拒绝后不产生删除副作用 | FR-052~055 |
| AC-008 | 读取超大日志文件 | 返回受限的头尾内容、截断标记和省略量 | FR-022、030 |
| AC-009 | 逼近上下文上限 | 旧历史被压缩，用户目标、约束、近期工具结果仍存在 | FR-021~024 |
| AC-010 | 用户在执行中发送取消 | 当前命令被终止，状态为 `cancelled`，会话可继续使用 | FR-003、042、044 |
| AC-011 | API key 无效 | 不重试认证错误，不泄露 key，退出信息包含修复建议 | FR-004、013、054 |
| AC-012 | 使用 `--json` 执行成功任务 | stdout 最终对象符合接口文档 schema，退出码为 0 | FR-002、063 |
| AC-013 | 工具执行抛出内部异常 | 转为 `INTERNAL_ERROR` 工具结果，主循环不崩溃 | NFR-003 |
| AC-014 | Windows junction 指向工作区外 | 读写请求被拒绝 | FR-050、NFR-001 |
| AC-015 | 使用假模型按预设脚本返回工具调用 | 无公网条件下端到端测试可重复通过 | NFR-004 |
| AC-016 | 在两个工作区各放置同名文件，并把任务绑定到第二个工作区 | 补丁和文件预览只作用于第二个工作区，第一个工作区保持不变 | FR-001、030~034、050 |

## 9. 退出码

| 退出码 | 含义 |
|---:|---|
| 0 | 任务正常完成 |
| 1 | 通用运行失败 |
| 2 | 命令行参数或配置无效 |
| 3 | 模型服务不可用或请求最终失败 |
| 4 | 达到循环限制或上下文限制 |
| 5 | 用户取消 |
| 6 | 安全策略阻止且无法继续 |

## 10. MVP 完成定义

同时满足下列条件才视为 MVP 完成：

- 实现 FR 中所有 `MUST` 项；
- AC-001 至 AC-015 均有自动化测试或可重复的测试脚本，其中安全相关用例必须自动化；
- 使用至少两个小型示例仓库完成“新增功能”和“修复缺陷”任务；
- 核心端到端测试使用假模型，无需真实 API key；
- 项目文档包含安装、配置、安全边界、演示命令和已知限制；
- 未引入被禁止的 Agent 框架或服务端代码/文件工具。
